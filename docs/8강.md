# 8강 — 확장과 재사용: 한 번 만든 일을 스킬로 만들어 나누기

**실습 자료**: `AX 직무 역량검사_강의자료(+실습대상)/8강/`

```
1.주문통합/   웹주문.xlsx · 전화주문.csv · 제휴주문.xlsx · 주문통합_작업지침.md
2.견적통합/   견적_대성테크.csv · 견적_유진상사.xlsx · 견적_한빛산업.xlsx
3.스킬예시/   SKILL.md            ← 형식(frontmatter)만 참고하는 예시
```

**결과물**
- `1.주문통합/종합주문.xlsx` (91행)
- `2.견적통합/견적비교표.xlsx` (36행)
- `.claude/skills/데이터통합/SKILL.md`

**결과 참고**: `결과참고/8강/` (`.claude/skills/데이터통합/SKILL.md`, 종합주문, 견적비교표, 작업지침)

## 1. 이 차시는 작업 유형 6가지 밖에 있다

1~7강은 (1)~(6) 작업 유형을 하나씩 훑었다. 8강은 그 위에 있다 — **한 번 한 일을 다시 쓰는 방법.**

> **"누구의 폴더에서도 돌아갈 수 있도록 범용화해서 스킬화하는 작업을"**

## 2. 재사용의 3가지 방식

| **동일 업무에 적용** | **비슷한 다른 업무에 응용** | **동료에게 공유** |
|---|---|---|
| 다음 달 주문도 같은 절차로 | 주문 → 견적으로 | 폴더째 전달 |

> **"내가 만든 업무 프로세스를 옆자리 동료에게 그대로 전달할 수가 있습니다"**

이 차시의 실습 4개가 이 3가지를 순서대로 밟는다.

| 실습 | 재사용 방식 |
|---|---|
| ① 작업지침 범용화 | (준비) 특정 파일 의존을 떼어낸다 |
| ② 주문 통합 실행 | **동일 업무에 적용** |
| ③ 스킬로 만들기 | (준비) 절차를 파일로 고정 |
| ④ 견적에 적용 | **비슷한 다른 업무에 응용** |
| — | **동료에게 공유** = 스킬 폴더를 압축해서 보내기 |

## 3. 스킬을 실행하는 3가지 방법

| # | 방법 |
|---|---|
| 1 | **`/스킬명`을 입력해 직접 실행** (`/데이터통합`) |
| 2 | **자연어로 특정 스킬의 사용을 요청** ("데이터통합 스킬을 써서") |
| 3 | **작업에 필요하다고 판단하면 AI가 자동으로 불러와 사용** |

3번이 되려면 frontmatter의 `description`에 **언제 켜야 하는지**가 적혀 있어야 한다. 그래서 스킬 설명은 "무엇을 하는가"보다 **"어떤 요청에서 켜지는가"**가 중요하다.

## 실습 ① — 작업지침을 범용 절차로

### 프롬프트

> 이 `주문통합_작업지침.md`은 지금 특정 파일명과 특정 열 이름에 맞춰져 있어. 이걸 **어떤 파일이 와도 쓸수 있도록 범용 절차**로 다시 써줘.
> - 파일명을 고정하지 말고 '폴더 안의 표 파일을 전부 찾는다'로, 열 이름도 고정하지 말고 '각 열이 주문번호인지·고객명인지·금액인지 내용을 보고 표준 칸에 맞춘다'로 바꿔줘.
> - 표준 7칸(주문번호·고객명·상품명·수량·금액_원·주문일·출처채널), 날짜 `YYYY-MM-DD`, 금액 콤마 제거, 중복은 한 줄, 빈칸은 비워두기, 행 수 검산 — 이 규칙은 그대로 유지해.
> - 열 이름이 애매해서 어느 칸에 넣을지 모르겠으면 **지어내지 말고 나한테 물어봐.**

**"이건 바꾸고 이건 유지해"를 명확히 나눈 프롬프트다.** 범용화하라고만 하면 규칙까지 같이 뭉개진다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 대상 파일 | `웹주문.xlsx`·`전화주문.csv`·`제휴주문.xlsx` **3개 고정** | 폴더 안 `.xlsx`/`.csv` **전부 탐색** |
| 열 매핑 | 파일별 열 이름 18개 나열 | **"이렇게 생겼으면 → 이 칸"** 판단 기준표 |
| 출처채널 | 웹/전화/제휴 3값 고정 | **파일명 기준** |
| 애매할 때 | (없음) | **5장 신설 — 매핑표 확인받고 진행** |
| 표준 7칸·날짜·콤마·중복·빈칸·검산 | | **그대로 유지** |

기존 결과물을 대상에서 빼는 조항도 넣었다 — **두 번 돌리면 자기 출력을 다시 먹는다.**

## 실습 ② — 범용 지침으로 주문 통합 (동일 업무에 적용)

### 프롬프트

> 주문통합 폴더안의 웹주문, 전화주문, 제휴주문을 하나의 종합주문 파일로 만들어줘

**열 이름도 규칙도 없다.** 파일 3개만 지목했고 나머지는 지침이 채웠다. **이게 범용화의 값어치다** — 프롬프트가 짧아진다.

### 열 매핑 — 내용을 보고 판단

| 표준 칸 | 웹주문.xlsx | 전화주문.csv | 제휴주문.xlsx |
|---|---|---|---|
| 주문번호 | 주문번호 | `order_id` | 협력사주문ID |
| 고객명 | 고객명 | `name` | 구매자 |
| 상품명 | 상품 | `item` | 품목 |
| 수량 | 수량 | `qty` | 개수 |
| 금액_원 | 금액 | `amount` | 결제액 |
| 주문일 | 주문일시 | `date` | 일자 |

날짜 표기가 파일마다 달랐다 — `2026-01-07 15:00` / `2026/01/10` / **`01/15/2026`(월-일-년)**. 셋 다 `YYYY-MM-DD`로 통일.

### 결과 — `종합주문.xlsx` 91행

| 검산 | 결과 |
|---|---|
| 파일별 행 수 | 33 + 32 + 31 = **96** |
| 중복 제거 | **5건** |
| 통합 후 | 96 − 5 = **91** ✅ |
| 금액 합계 | 45,030,000 → 43,087,000 (중복분 1,943,000 제외) ✅ |
| 날짜 형식 위반 / 빈칸 | 0 / 0 |

중복 5건은 **같은 주문번호 + 같은 고객명**이 두 채널에 잡힌 건이었다(ORD-26170 표유준, ORD-26285 문서현, ORD-26500 윤시우, ORD-26963 류하준, ORD-26966 조수아).

## 실습 ③ — 절차를 '데이터통합' 스킬로

### 프롬프트

> - 방금 만든 이 범용 주문통합 절차를 **'데이터통합'이라는 스킬로 만들어줘.**
> - 언제 이 스킬을 써야 하는지(여러 파일을 한 표로 합칠 때) 트리거 설명을 넣고,
> - 절차는 '폴더에서 표 파일 찾기 → 각 열의 의미 파악 → 표준 칸 매핑 제안 → 나한테 확인 → 통합 → 행 수 검산' 순서로,
> - 원칙은 '1. 빠뜨리지 않기 2. 바꾸지 않기 3. 지어내지 않기'를 꼭 넣어줘.
>
> 참고로 같은 폴더의 `3.스킬예시/SKILL.md`가 이미 거의 같은 내용의 예시라, 형식(frontmatter 구성)만 참고하고 문구는 새로 작성했어.

**예시 파일을 "형식만" 쓰는 게 지시의 핵심.** 내용까지 베끼면 내 절차가 아니라 남의 절차가 된다.

### 작업지침(문서)과 스킬의 차이

| | 범용화한 작업지침 | 스킬 |
|---|---|---|
| 표준 칸 | **주문 7칸 고정** | **자료 종류에 따라 달라진다**고 명시 |
| 중복 처리 | 주문번호 기준 제거 | **키가 없으면 제거 대신 비교되게 모은다** 분기 추가 |
| 범위 | 주문 통합 전용 | 표를 합치는 일 전반 |

작업지침은 "주문을 범용으로", 스킬은 **"통합이라는 일 자체를 범용으로"**다. 실습 ④에서 이 차이가 결과를 갈랐다.

### 스킬 위치

```
8강/.claude/skills/데이터통합/SKILL.md
```

> **"아까 만들어진 이 [데이터통합] 폴더를 그대로 압축해서 동료에게 보내주기만 하면 됩니다"**

**폴더 하나가 배포 단위다.** 이게 "동료에게 공유"가 성립하는 이유.

## 실습 ④ — 스킬을 견적에 적용 (비슷한 다른 업무에 응용)

### 프롬프트

> - `2.견적통합` 폴더의 견적 파일들에 **'데이터통합' 스킬을 써서** 한 표로 합쳐줘. 이번엔 견적이니까 표준 칸은 품목·규격·수량·단가·납기로 잡고, 같은 품목은 업체별로 비교되게 모아줘. 결과는 해당 폴더안에 `견적비교표.xlsx` 파일로 저장해줘.

**주문과 완전히 다른 자료인데 같은 절차가 그대로 돌았다.** 표준 칸만 바뀌었다. 스킬 실행 방법 3가지 중 **2번(자연어로 특정 스킬 사용 요청)**에 해당한다.

### 열 매핑 — 세 파일 모두 열 이름이 다름

| 표준 칸 | 견적_대성테크.csv | 견적_유진상사.xlsx | 견적_한빛산업.xlsx |
|---|---|---|---|
| 품목 | `item_name` | 자재명 | 품목명 |
| 규격 | `spec` | 사양 | 규격 |
| 수량 | `qty` | 주문수량 | 수량 |
| 단가 | `unit_price` | 개당단가 | 단가 |
| 납기 | `delivery` | 납품예정일 | 납기일 |

날짜 표기도 셋 다 달랐다 — `2026.02.02` / `2026년 2월 2일` / `2026-02-03`.

표준 5칸 외에 **업체** 칸을 추가했다. 주문통합의 `출처채널`과 같은 역할이다.

### 주문 때와 갈린 처리 — 중복 제거를 하지 않았다

각 업체 파일 안에 **같은 품목+규격이 여러 줄** 있었다.

| 품목 | 규격 | 업체 | 건수 |
|---|---|---|---:|
| 사무용의자 | 메쉬형/팔걸이 | 유진상사 | 2 (70,800 / 81,100) |
| 포스트잇 | 76x76mm/12개입 | 대성테크 | 2 |
| 포스트잇 | 76x76mm/12개입 | 한빛산업 | 2 |
| 프린터토너 | HP CF283A 호환 | 유진상사 | 2 |
| 프린터토너 | 삼성 MLT-D101S | 유진상사 | 2 |
| 화이트보드마카 | 흑색/12자루 | 한빛산업 | 2 |

**이건 주문번호처럼 "같은 건을 두 번 적은 실수"가 아니다.** 수량·단가·납기가 다르니 서로 다른 견적이고, 임의로 합치거나 지우면 **"바꾸지 않기 / 빠뜨리지 않기"** 원칙에 어긋난다. 그래서 36행 전부 남겼다.

**견적에는 주문번호 같은 고유 키가 없다.** 같은 품목이 업체마다 나오는 게 정상이고, 그게 비교의 대상이다.

### 비교 가능하게 정렬

`품목 → 규격 → 업체` 순으로 정렬해서, 같은 품목·규격이 붙어 업체별 단가가 바로 비교되게 했다.

```
A4용지  75g/A4/2500매   5  21,600  대성테크
A4용지  75g/A4/2500매   3  20,400  유진상사
A4용지  75g/A4/2500매  29  20,000  한빛산업   ← 세 업체가 나란히
```

### 검산

| 항목 | 결과 |
|---|---|
| 원본 행 수 합계 | 11 + 13 + 12 = **36** = 통합 후 36 (제외한 행 없음) ✅ |
| 단가 합계(콤마 제거 기준) | **1,379,200** = 결과 합계 1,379,200 ✅ |
| 결측치 / 날짜 형식 위반 | 0건 / 0건 |

## ⚠️ 강의 결과와 갈린 지점

강의 화면의 최종 결과와 대조했다.

### 일치

| 항목 | 강의 | 이 저장소 |
|---|---|---|
| 견적비교표 행 수 | 36 (제외한 행 없음) | 동일 |
| 단가 합계 | 1,379,200 = 1,379,200 | 동일 |
| 결측치 | 0건 | 동일 |
| 중복 제거 판단 | **하지 않음** — 실수가 아니라 서로 다른 견적 | 동일 |
| 추가 칸 | 업체 (출처채널과 같은 역할) | 동일 |
| 정렬 | 품목→규격→업체 | 동일 |

### 갈렸다가 되돌린 것 — 비교표 형태

처음에는 **품목당 1행, 업체를 열로 펼친 wide 표**(10행) + 원본 36행을 별도 시트로 만들었다. 최저단가·최저업체·가격차까지 계산해 붙였다.

**그런데 이건 원칙 위반이었다.** wide 표는 한 칸에 값 하나만 들어가므로, 같은 업체가 낸 견적 2건 중 하나를 골라야 한다. 최저가만 남기는 순간 **6건이 정본에서 사라진다.** "빠뜨리지 않기"에 어긋난다.

강의 방식(36행 long 단일 시트)으로 다시 만들었다. **정렬만으로도 업체별 비교는 충분히 되고, 아무것도 버리지 않는다.**

| | 처음 만든 것 | 다시 만든 것 (강의 방식) |
|---|---|---|
| 형태 | wide 비교표 10행 + 원본 36행 (2시트) | **long 36행 (1시트)** |
| 같은 업체 중복 견적 | 비교표에서 **6건 가려짐** | 전부 보임 |
| 최저가 계산 | 미리 해서 붙임 | 안 함 (보면 알 수 있음) |

**"보기 좋게 가공하는 것"과 "빠뜨리지 않는 것"이 부딪히면 후자가 이긴다.** 가공은 사람이 나중에 할 수 있지만, 버린 데이터는 되돌릴 수 없다.

### 스킬 위치

처음에 저장소 루트 `.claude/skills/`에 만들었다가, 강의대로 **`8강/.claude/skills/`**로 옮겼다. 스킬 폴더는 **압축해서 보내는 배포 단위**이므로, 그 자료와 같은 자리에 있어야 "이 폴더째 보내면 끝"이 성립한다.

## 실습 중 걸린 함정 — macOS 파일명 유니코드

`견적_대성테크.csv`에서 `"견적_"`을 떼어내 업체명을 만들었는데, 결과에 **`견적_대성테크`가 그대로 남았다.**

macOS 파일시스템은 한글 파일명을 **NFD**(자모 분리)로 저장하는데, 코드에 쓴 `'견적_'`은 **NFC**(완성형)라서 문자열이 안 맞은 것이다. 눈에는 똑같이 보인다.

```python
files = glob.glob('견적*')   # → 내가 만든 파일 1개만 잡힘 (NFC)
```

## 이 차시에서 건진 것

- **범용화는 "무엇을 고정하지 않을지"를 정하는 일이다.** 파일명과 열 이름을 떼어내되 규칙(표준 칸·날짜·검산)은 그대로 둔다. 둘을 같이 뭉개면 아무 데서나 도는 대신 아무것도 보장 못 하는 절차가 된다.
- **범용화하면 프롬프트가 짧아진다.** 실습 ②는 파일 3개만 지목했는데 열 매핑·날짜 통일·중복 제거·검산이 다 나왔다.
- **"애매하면 물어봐"를 절차에 못박는다.** 5강의 "추측이면 추측이라고 표시해라", 7강의 "확인 필요"와 같은 자리다. 8강에서는 아예 **매핑표를 확인받고 진행**하는 단계로 승격됐다.
- **스킬 설명은 "무엇을 하는가"가 아니라 "언제 켜지는가"다.** AI가 자동으로 불러오려면(실행 방법 3번) 트리거 문구가 있어야 한다.
- **같은 절차라도 자료 성격에 따라 분기해야 한다.** 주문은 키가 있어 중복 제거, 견적은 키가 없어 비교 정렬. **이 분기를 스킬에 미리 적어둔 게 실습 ④를 살렸다.**
- **중복처럼 보인다고 다 중복이 아니다.** 같은 품목+규격 6건은 수량·단가·납기가 달라 서로 다른 견적이었다.
- **보기 좋은 가공이 원칙과 부딪히면 원칙이 이긴다.** wide 비교표는 예뻤지만 6건을 가렸다.
- **배포 단위는 폴더 하나다.** `.claude/skills/데이터통합/`을 압축해 보내면 동료 환경에서 그대로 돈다 — 이게 재사용 3번째 방식의 실체.
- **한글 파일명은 NFC 정규화부터.** macOS는 NFD로 저장해서 눈에 같아 보여도 문자열이 안 맞는다.
