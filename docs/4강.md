# 4강 — 딱지 붙이기: 글을 범주로 분류

**실습 자료**: `AX 직무 역량검사_강의자료(+실습대상)/4강/`
- `1. VOC원문.xlsx` — 고객 문의 520건 (원 데이터)
- `2. VOC_분류기준.pdf` — 분류 기준 문서 (이 차시에서 AI와 함께 만든 작업 지침)
- `3. 분류표.xlsx` — 채워넣을 결과물 (item_id·채널·문의유형·감성·위험대응)

**결과 참고**: `결과참고/4강/3. 분류표_결과참고.xlsx`

---

## 1. 작업 유형 6가지 중 (3) 딱지 붙이기

| (1) 데이터 만들기 | (2) 자료 요약 | **(3) 딱지 붙이기** | (4) 분석하기 | (5) 보고자료 만들기 | (6) 확인하고 수정하기 |
|---|---|---|---|---|---|

> **딱지 붙이기 — 자료의 내용을 정해진 규칙에 따라 범주로 분류하는 작업**

1강의 구분을 다시 보면, 딱지 붙이기(③)는 **정답이 모호**하고 확인하고 수정하기(⑥)는 정답이 규칙으로 정해져 있다. 그래서 이 작업은 **"정해진 규칙"을 누가 만드느냐**가 통째로 문제가 된다.

## 2. 이 차시의 진짜 주제 — 지침을 AI와 같이 만든다

> **"어떻게 AI한테 제대로 된 지침을 만들어서 줄 수 있죠?"**
>
> **"이 [1. VOC원문]을 주고 AI에게 지침을 한번 만들어 보라고 시켜보는 거예요"**
>
> **"오늘은 작업을 시킬 작업 지침 자체를 AI와 함께 협업을 해서 만들어 보았고, AI에게 딱지 붙이기 작업을 시켜 보았습니다"**

앞 차시들과 순서가 다르다.

| | 2·3강 | **4강** |
|---|---|---|
| 지침 | 강사가 준 파일(`작업방법참고.xlsx`)을 읽힘 | **원 데이터를 주고 AI에게 지침을 만들게 함** |
| 그 다음 | 지침대로 작업 | 그 지침으로 작업 |

분류는 정답이 모호해서 **기준이 없으면 사람마다 답이 갈린다.** 그러니 기준 문서를 먼저 만들고, 그걸 다음 작업의 입력으로 쓴다. 실습이 프롬프트 2개로 나뉜 이유가 이것이다.

---

## 실습 1 — 분류 기준 만들기

### 프롬프트

> 작업폴더 안에 고객문의가 정리된 'VOC_원문' 이라는 파일이 있어 해당 파일을 살펴보고 문의유형 / 감정 / 위험대응 세가지 부분의 분류를 만들려고 해
> 어떤 기준으로 해야 잘 분류할 수 있을지 기준을 만들어봐
> 단, 문의유형은 환불취소 / 배송지연 / 제품하자 / 사용문의 / 칭찬감사 로 분류하고 분류기준에 없으면 기타로 해줘
> 감정분류는 긍정 / 부정 / 중립 으로 해주고
> 긴급 대응이 필요한 건 여론에 심각한 영향을 줄 가능성이 있거나 제품에 뭔가 결함이 있다는 내용 등 기업입장에서 긴급한 대응이 필요할 것으로 예상되는 일을 판단하면 돼

**"기준을 만들어봐"라고만 하지 않고 라벨 목록을 못박은 게 핵심.** 세 축의 값을 열어두면 AI가 자기 마음대로 범주를 늘려서, 다음 작업에서 쓸 수 없는 기준이 나온다. 자유롭게 정하게 둔 건 **"어떤 근거로 그 라벨을 붙일지"**뿐이다.

원문 520건을 훑어 나온 데이터 구조:

```
L-021  커튼 정말 만족스럽게 잘 쓰고 있어요. 감사합니다.        ← ① 본문(칭찬)
       다만 지난번 문의드린 건은 아직도 해결이 안 되고 있어서,   ← ② 꼬리(불만)
       소비자원에 신고하는 것까지 생각하고 있습니다.            ← ③ 위험 문구
```

**한 건이 서로 다른 방향의 신호를 동시에 갖는다.** 그래서 기준의 본질은 "어떤 단어가 나오면 뭐다"가 아니라 **어느 조각을 보고 판단하고, 충돌하면 무엇이 이기는지**다.

## 실습 2 — 520건 분류

### 프롬프트

> 'VOC_원문' 파일에 고객들의 문의가 들어있어 각 문의 내용을 읽고 '분류표' 파일의 내용을 작성해줘 문의유형/감성은 'VOC_분류기준' 파일의 내용에 따라서 분류하고 신속한 위험대응이 필요한 경우 위험대응칸에 '대응필요' 라고 채워줘

앞 단계에서 만든 기준 PDF를 **입력 파일로 다시 넣는다.** 프롬프트에 기준을 옮겨 적지 않는다 — 2강 `작업방법참고.xlsx`, 3강 "열 머리를 참조하여"와 같은 발상.

### 기준 PDF가 확정해준 것

기준 문서 없이 원문만 보고 세웠던 초안에서 두 군데가 갈렸는데, PDF가 답을 줬다.

| 쟁점 | 기준 PDF | 초안 판단 |
|---|---|---|
| 교환 요청 38건 | **환불취소** ("환불·취소·반품·**교환** 등 거래 변경을 요청") | 일치 |
| 위험대응의 제품 신호 | **안전 위험(화재·부상·감전·유해물질)만**. 일반 제품하자는 제외 | **틀림** — 제품하자 전체를 넣으려 했음 |

두 번째를 그대로 갔으면 위험대응이 68건이 아니라 170건이 됐다. **"제품에 결함이 있다는 내용"이라는 프롬프트 문구를 기준 문서가 "안전 위험"으로 좁혀준 것** — 지침을 문서로 한 번 거치는 단계가 왜 필요한지 보여주는 지점.

### 결과

| 문의유형 | 건수 | | 감성 | 건수 | | 위험대응 | 건수 |
|---|---:|---|---|---:|---|---|---:|
| 환불취소 | 111 | | 부정 | 265 | | **대응필요** | **68** |
| 배송지연 | 110 | | 중립 | 181 | | 공백 | 452 |
| 제품하자 | 91 | | 긍정 | 74 | | | |
| 사용문의 | 89 | | | | | | |
| 칭찬감사 | 89 | | | | | | |
| 기타 | 30 | | | | | | |

위험 68건 = 법적대응 예고 53 + 여론확산 위협 15. **안전 위험은 0건**(원문에 화재·감전·부상 표현이 없음).

### 판정에서 갈린 지점

**① 부수적인 응대 칭찬을 본 사안에서 분리.** 기준 PDF의 "칭찬은 부수 표현이므로 본 사안으로 분류" 조항.

| 표현 | 건수 |
|---|---:|
| 그래도 상담원분이 친절해서 감사했어요 | 16 |
| 그래도 처리 속도는 최고였어요 | 15 |
| 그나마 응대는 만족스러웠습니다 | 13 |
| 그래도 응대는 친절해서 다행이었어요 | 8 |

떼지 않으면 **24건이 긍정으로 잘못 올라간다.** L-002 "초기 설정을 어떻게 하는지 궁금해요. 그래도 응대는 친절해서 다행이었어요" → 본 사안은 담백한 질문이므로 중립.

**② 위험 68건 중 18건은 감성이 긍정.** 기준 PDF가 "주의할 함정"으로 명시한 케이스다.

> L-035 "덕분에 잘 해결됐어요. 정말 감사합니다. 다만 안내받았던 보상 건은 아직 처리가 안 된 것 같은데, 계속 지연되면 **법적대응** 할 생각입니다."

감성으로 위험을 걸렀으면 18건을 통째로 놓친다. **위험대응은 감정·유형과 무관하게 문장 단위로 독립 스캔**한다는 게 기준의 핵심.

## 실습 3 — 검산

### 프롬프트

> 먼저 문의유형과 감성에 빈칸이 없는지 확인해보고 기준대로 잘 작업 되었는지 한번 더 확인해봐

집계(3강)는 숫자가 맞는지 보면 되지만, **분류는 맞았는지를 숫자로 증명할 수 없다.** 그래서 검산 방향이 다르다.

| 검산 | 내용 | 결과 |
|---|---|---|
| 빈칸 | item_id·채널·문의유형·감성 | 전부 0건 |
| 허용값 | 정의된 라벨 외 값이 있나 | 유형 6종·감성 3종·위험 2종만 |
| **일관성** | 같은 문장이 다른 라벨을 받았나 | 고유 패턴 258종 중 **갈린 것 0종** |
| 기준 예시 대조 | PDF에 적힌 예시 문구 17종의 실제 라벨 | 불일치 0종 |
| 우선순위 규칙 | PDF의 복합문의 3개 조항 | 위반 0건 |
| 감정 규칙 | 이모티콘·담백한 요청·혼재 | 위반 0건 |
| 위험 독립성 | 위험 문구 68건 누락·오탐 | 각 0건 |
| 기타 30건 | 다른 유형 키워드를 품었나 | 0건 (전부 순수 잡담) |

**일관성 검사가 분류 작업 고유의 검산이다.** 정답을 모르니 "같은 입력에 같은 답을 냈는가"를 대신 본다. 520건을 한 건씩 감으로 읽으면 가장 먼저 새는 지점이 여기다.

## ⚠️ 강의 결과와 갈린 지점

강의 화면에 나온 분류 결과 20건과 대조한 결과 **18건 일치 / 2건 불일치**.

| item | 강의 | 이 저장소 |
|---|---|---|
| L-021 | 기타 / 부정 / 대응필요 | 칭찬감사 / **긍정** / 대응필요 |
| L-035 | 기타 / 부정 / 대응필요 | 칭찬감사 / **긍정** / 대응필요 |

둘 다 **"칭찬 본문 + 다만 불만 꼬리 + 위험 문구"** 패턴이고, 원문 전체에 이 패턴이 **18건** 있다.

근거가 갈리는 이유는 기준 PDF 안에 서로 다르게 읽히는 두 문장이 있어서다.

| 조항 | 이렇게 읽으면 |
|---|---|
| 판정 순서 2 — "감정 판정, 혼재 시 **부정 우선**" | 꼬리가 불만이므로 **부정** (강의 쪽) |
| 위험대응 함정 — "'만족스럽게 잘 쓰고 있어요. 소비자원에 고발 조치도…'처럼 **감정이 긍정이어도** 위험 신호가 있으면 무조건 Y" | 이 예시 자체를 **긍정**으로 전제 (이 저장소 쪽) |

**실무 영향은 없다** — 양쪽 다 위험대응 `대응필요`로 잡히므로 놓치는 건이 없다. 갈리는 건 감성 통계뿐. 정답이 모호한 작업이라 기준 문서에 이런 틈이 남으면 이렇게 갈린다는 것 자체가 이 차시의 교훈.

## 이 차시에서 건진 것

- **지침을 AI에게 만들게 하되, 라벨 목록은 사람이 못박는다.** 값을 열어두면 다음 작업에 못 쓰는 기준이 나온다. 자유를 주는 건 "무슨 근거로 붙일지"까지.
- **지침을 파일로 떨어뜨려 다음 작업의 입력으로 쓴다.** 2강 작업방법참고 → 3강 열 머리 참조 → 4강 기준 PDF. 세 차시 연속 같은 패턴이고, 여기서는 그 파일을 **AI가 만들었다**는 점만 다르다.
- **모호한 지시는 기준 문서를 거치며 좁혀진다.** "제품에 뭔가 결함이 있다는 내용"(프롬프트) → "안전 위험: 화재·부상·감전·유해물질"(기준 PDF). 이 한 단계가 없었으면 위험대응이 2.5배로 부풀었다.
- **분류의 검산은 "정답 대조"가 아니라 "일관성 + 규칙 준수"다.** 집계와 달리 합계로 맞출 수가 없다.
- **위험 판정은 감정 판정에 종속시키면 안 된다.** 긍정으로 시작하는 문의 18건에 법적대응·신고 예고가 들어 있었다.
- 기준 문서에 틈이 있으면 결과가 갈린다 — 위 L-021·L-035 건. 기준을 만들 때 **"혼재"의 방향(부정 본문+긍정 꼬리 / 긍정 본문+부정 꼬리)을 나눠서** 적어야 했다.
