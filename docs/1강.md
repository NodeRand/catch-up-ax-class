## 1. 신입사원의 반복업무는 결국 이 6가지 작업의 조합

| 코드 | 정식 이름 | 쉬운 이름 | 입력 → 출력 | 한 줄 판별 |
|---|---|---|---|---|
| ① | 추출/파싱 | **데이터 만들기** | 비정형(PDF·이미지) → 표 | "구조 없던 걸 표로 만든다" |
| ② | 취합/통합 | **자료 요약** | 정형 다수 → 정형 하나 | "행을 보존하며 여러 파일을 합친다" |
| ③ | 분류 | **딱지 붙이기** | 텍스트 → 범주 라벨 | "이게 뭐냐(정답이 모호)" |
| ④ | 집계/분석 | **분석하기** | 정형 → 요약·지표 | "행을 줄여 수치·인사이트로" |
| ⑤ | 초안 작성 | **보고자료 만들기** | 자료 → 새 산문 | "없던 보고서를 쓴다" |
| ⑥ | 검수/수정 | **확인하고 수정하기** | 데이터+규칙 → 위반 판정 | "규칙에 맞냐(정답이 규칙)" |

**②와 ④를 헷갈리지 말 것** — 합치기(②)는 행을 보존하고, 분석(④)은 행을 줄인다.
**③과 ⑥도 짝으로 기억** — 분류(③)는 정답이 모호하고, 검수(⑥)는 정답이 규칙으로 정해져 있다.

## 2. 프롬프트 엔지니어링 vs 컨텍스트 엔지니어링

| | 프롬프트 엔지니어링 | 컨텍스트 엔지니어링 |
|---|---|---|
| 무엇을 설계하나 | AI가 원하는 답을 내도록 **질문과 지시문**을 설계 | AI가 작업을 제대로 수행하도록 필요한 **정보와 도구가 적절한 시점에** 제공되도록 **작업 맥락**을 설계 |

말을 잘 거는 것(프롬프트)에서, 일할 판을 깔아주는 것(컨텍스트)으로 관점이 넘어간다.

### 컨텍스트 엔지니어링 예시 — 상황: 기업 재무상황 분석

앞의 6가지 작업 유형을 한 상황에 이어붙이면 이렇게 된다.

| 작업 유형 | 무엇을 맥락으로 제공하나 |
|---|---|
| (1) 데이터 만들기 | 공식 재무제표를 AI에 제공해 주요 재무지표 추출 |
| (2) 자료 요약 | AI에게 기사·공시자료 등 **찾아볼 자료의 범위**를 알려 분기별 실적을 수집·정리 |
| (4) 분석하기 | **분석 목적과 기준**을 제시해 기업의 재무상황을 분석, 인사이트 도출 |
| (5) 보고자료 만들기 | **보고 대상과 형식**을 알려 AI로 보고자료 작성 |
| (6) 확인하고 수정하기 | **검토 기준과 수정사항**을 전달해 오류·누락 보완 |

각 줄에서 굵게 표시한 부분이 곧 "AI에게 미리 깔아줘야 할 맥락". 이 예시에는 (3) 딱지 붙이기는 등장하지 않는다.

## 3. AI 업무 지시의 핵심 요소

```
     입력          →         방법         →        출력
제공할 자료와 정보     자료를 처리할 기준과 방식     결과물의 내용과 형식
```

여기에 더해 **이 업무의 배경과 목표**까지 주면 지시가 완성된다.

## 실습 — 재고자산 현황 정리 (⑥ 확인하고 수정하기)

정답이 "규칙"으로 정해져 있는 전형적인 검수/수정 작업. 실제로 던진 프롬프트와 그 분해:

### 프롬프트 1 — 품목코드 형식 교정

> '재고자산_현황' 파일의 첫 번째 열에 있는 품목코드는 2개의 대문자와 '-' 그리고 세자리의 숫자로 조합된 코드야 이 형식에 맞지 않는 코드를 수정해줘

| 요소 | 프롬프트에서 해당하는 부분 |
|---|---|
| 입력 | '재고자산_현황' 파일의 첫 번째 열 |
| 방법 | 대문자 2개 + `-` + 숫자 3자리 형식에 맞지 않는 것을 찾아 |
| 출력 | 그 코드를 수정 |

**결과**: 61행 중 3건 수정.

| 행 | 수정 전 | 수정 후 | 위반 내용 |
|---|---|---|---|
| 4 | `el-003` | `EL-003` | 소문자 |
| 5 | `EL004` | `EL-004` | 하이픈 누락 |
| 27 | `SF010` | `SF-010` | 하이픈 누락 |

### 프롬프트 2 — 보관창고 표기 통일

> 같은 파일에 네번째 열은 보관된 창고를 정리해둔건데 본사 / 서울창고 / 부산창고 세개의 분류가 있는데 여러가지 형태로 작성되어 있어 확인하고 열 머리에 이미 보관창고라고 되어 있으니 본사 / 서울 / 부산 으로만 정리하면 돼 수정해봐

| 요소 | 프롬프트에서 해당하는 부분 |
|---|---|
| 입력 | 같은 파일 네 번째 열(보관창고), 분류는 본사/서울/부산 세 개 |
| 방법 | 여러 형태로 적힌 표기를 확인 — 열 머리가 이미 '보관창고'라 '창고'는 중복 |
| 출력 | 본사 / 서울 / 부산 세 값으로만 |

**결과**: 6개 표기 변형 → 3개로 통일.

| 수정 전 | 수정 후 | 건수 |
|---|---|---|
| 서울창고 | 서울 | 31 |
| 서울 창고 (공백 포함) | 서울 | 3 |
| 부산창고 | 부산 | 11 |
| 본사창고 | 본사 | 5 |

최종 분포: 서울 42 / 부산 11 / 본사 8 (총 61행).

### 실습에서 건진 것

- 프롬프트 2가 좋은 예시였던 지점: **"열 머리에 이미 보관창고라고 되어 있으니"** — 왜 '창고'를 떼야 하는지 이유를 같이 줬다. 규칙만 던지는 것과 규칙의 근거까지 주는 것의 차이.
- 요청 범위 밖의 문제는 **고치지 말고 보고만** 했다. `EL-006`, `SF-010`이 각각 2행씩 중복이고, 수량 결측·날짜 형식 혼재(`2024-01-15` / `2024/02/03` / `24.02.10` / `3월 12일`)도 남아 있다. 이후 차시 소재일 가능성.
