# 3강 — 자료 요약: 숫자와 인사이트로 집계

**실습 자료**: `AX 직무 역량검사_강의자료(+실습대상)/3강/`
- `6.GA5_주문종합.xlsx` — 주문 9,389행 (2강에서 모은 것과 같은 성격의 종합 파일)
- `7.쿠폰별성과표.xlsx` — 채워넣을 빈 집계 양식 (쿠폰코드 44개)

**결과 참고**: `결과참고/3강/7.쿠폰별성과표_결과참고.xlsx`

## 1. 작업 유형 6가지 중 (2) 자료 요약

| (1) 데이터 만들기 | **(2) 자료 요약** | (3) 딱지 붙이기 | (4) 분석하기 | (5) 보고자료 만들기 | (6) 확인하고 수정하기 |
|---|---|---|---|---|---|

> **자료 요약 — 데이터를 통계적 지표로 요약하는 작업**

2강(데이터 만들기)에서 흩어진 자료를 한 표로 모았다면, 3강은 **그 모은 표를 지표로 줄이는** 단계다. 행이 보존되지 않고 줄어든다는 점이 2강과 다르다.

### [EX] 자료 요약을 통한 쿠폰별 성과 파악

```
첫 주문 감사 쿠폰 사용 주문:   250건
신규 가입 축하 쿠폰 사용 주문:  350건
여름 맞이 할인 쿠폰 사용 주문: 1,000건
주말 한정 할인 쿠폰 사용 주문: 1,520건
        ⋮
```

> **약 9,000건의 쿠폰 사용 주문 기록을 쿠폰별 성과 지표로 요약**

이번 차시 실습의 구조가 곧 이 예시다.

| | |
|---|---|
| 입력 | 데이터 모으기로 종합한 파일 (`GA5_주문종합`) |
| 축약 | **주문 ID 기준 9,000행 → 44개 쿠폰코드 기준으로 자료 요약** |
| 조건 | **주문 취소 건은 제외** |

## 실습 — 쿠폰별 성과표 집계

### 프롬프트 1 — 지침 9개를 번호로 나열

> 아래의 지침들을 준수하여 업무를 수행하고 결과물을 생성해주세요.
> 1. GA5_주문종합 파일의 데이터를 사용하여 아래의 작업을 수행하세요.
> 2. 쿠폰코드를 기준으로 자료를 종합하여 결과물을 만드세요.
> 3. 자료를 종합할 대상은 \*\*`주문상태`가 '결제완료'인 주문만\*\* 종합하세요.
> 4. 결과는 '쿠폰별성과표'에 열 머리를 참조하여 채워넣으세요
> 5. 매출합계와 할인합계는 쿠폰코드를 기준으로 전부 합하고, 사용건수는 코드가 사용된 데이터의 수로 채워넣으세요.
> 6. 매출이익 = 매출합계 × 0.3 (매출원가를 제외한 이익만 종합)
> 7. 순이익 = 매출이익 − 할인합계
> 8. 매출 순이익률 = 순이익 ÷ 매출합계
> 9. 적자여부 = 순이익이 0보다 작으면 '적자', 아니면 빈칸을 표시하세요.

지시문 구조가 3덩어리로 나뉜다.

| 지침 | 역할 |
|---|---|
| 1·2 | **입력과 집계 기준** — 어떤 파일을, 무엇을 키로 묶을지 |
| 3 | **필터** — 취소 건 제외 |
| 4 | **출력 형식** — 양식의 열 머리를 참조해 채우기 (열 이름을 프롬프트에 다시 안 적어도 됨) |
| 5~9 | **계산 정의** — 파생 지표를 하나씩 수식으로 못박음 |

**지침 4가 이 프롬프트의 핵심.** "쿠폰별성과표에 열 머리를 참조하여"라고만 하면 열 이름·순서·서식을 프롬프트에 옮겨 적을 필요가 없다. 2강의 `작업방법참고.xlsx`와 같은 발상 — 규칙을 파일에 맡긴다.

### 프롬프트 2 — 검산 (강의가 특히 강조한 부분)

> 아래의 내용으로 검산해줘.
> ① '결제완료'만 셌는지 확인하고 취소 행은 몇 개였는지 알려줘.
> ② 집계표의 사용건수 총합이 결제완료 행 수와 정확히 같아?
> ③ 쿠폰별 총 이익률이 제대로 계산됐는지 몇개만 찝어서 다시한번 확인해보고 결과를 알려줘

> "꼭 검산하시는 과정이 필요하고요"

집계는 **행이 줄어드는 작업**이라 틀려도 눈에 안 띈다. 9,389행이 44행이 되고 나면 어디서 몇 건이 새어나갔는지 보이지 않는다. 그래서 검산 항목도 축약 과정을 되짚는 방향으로 짠다.

| 검산 | 무엇을 잡는가 |
|---|---|
| ① 필터가 걸렸나 | 조건(결제완료)을 빠뜨렸거나 반대로 적용한 경우 |
| ② 건수 총합 = 원본 행 수 | 집계 중 누락·중복 — **행 보존 여부의 유일한 증거** |
| ③ 파생 지표 표본 재계산 | 수식을 잘못 옮긴 경우 |

**① 결과** — 주문상태는 결제완료·취소 2종뿐. 취소 **1,067행** 제외됨.

| 기준 | 매출 총합 |
|---|---:|
| 집계표 매출합계 총합 | 709,453,463 |
| 결제완료만 합산 | 709,453,463 ← 일치 |
| 전체(취소 포함) 합산 | 967,528,590 ← 이 값이 아님 |

"필터를 걸었다"가 아니라 **안 걸었을 때 나왔을 값과 대조**해서 증명한다. 취소 행은 44개 코드 전부에 섞여 있어, 필터를 빠뜨렸다면 44행이 몽땅 틀어졌을 구조.

**② 결과** — 집계표 사용건수 총합 8,322 = 결제완료 행 수 8,322, **차이 0**. 쿠폰별 건수 44개도 개별 대조해 불일치 0.

## 이 차시에서 건진 것

- **집계는 "행이 줄어드는" 작업이라 검산이 필수다.** 2강 통합은 줄 수 산식(합계−중복=결과)으로 검산했고, 3강 집계는 **건수 총합 = 원본 행 수**로 검산한다. 축약 전후를 잇는 보존량을 하나 잡아두는 게 공통 패턴.
- **필터 검증은 "안 걸었을 때 값"과 대조한다.** "결제완료만 셌어?"에 "네"라고 답하는 건 증거가 아니다. 967,528,590 ≠ 709,453,463을 보여야 증거가 된다.
- **출력 양식을 파일에 맡긴다.** 지침 4의 "열 머리를 참조하여" 한 줄로 열 이름·순서·서식 지정을 통째로 생략했다.
- **파생 지표는 수식을 하나씩 못박는다.** 지침 6~9처럼 `매출이익 = 매출합계 × 0.3`을 문장이 아니라 등식으로 준다. "매출원가를 제외한 이익만 종합"이라는 **근거를 괄호로 덧붙인 것**은 1강 프롬프트 2와 같은 요령.
- 요청 범위 밖은 보고만 함 — 쿠폰별 취소율 편차가 크다 (CP19는 250건 중 56건 취소로 22%, CP44는 159건 중 12건으로 7.5%). 성과표에는 넣지 않았다. 성과표 J열에 `0.0%` 서식만 걸린 빈 열이 원래 있었는데 그것도 그대로 뒀다.
