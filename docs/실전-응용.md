# 실전 응용 — 배운 장치를 실제 문제에 대입하기

0강~8강에서 익힌 것을 **CATCH-UP AX 직무 역량검사** 실전 문제에 대입해 본 기록. 문제 풀이 과정이 아니라, **실전이 요구한 것 하나하나에 강의의 어느 장치가 대응하는가**를 정리한다.

---

## 나온 문제

| | 문제 1 | 문제 2 |
|---|---|---|
| 제목 | 계약서 기한·금액 만료·갱신 대상 추리기 | 청년정책 타게팅 홍보 대상자 추리기 |
| 입력 | 계약서 PDF 30건 | 정책 포스터 10개(jpg·png·pdf) + 회원 1,000명 명단 |
| 하는 일 | 종료일·자동갱신·통지일을 읽고 규칙 3개로 대상 판정 | 자격 조건을 읽고 회원과 10개 축으로 대조 |
| 출력 | 빈 엑셀 양식에 2칸 (계약번호·대상유형) | 빈 엑셀 양식에 2칸 (회원ID·추천정책ID) |
| 권장 시간 | 30분 | 50분 |

**둘 다 같은 골격이다.** 비정형 자료에서 조건을 읽어 표로 만들고 → 규칙으로 판정하고 → 빈 양식에 적는다. 1강의 작업 유형으로는 **① 데이터 만들기 + ⑥ 확인하고 수정하기**의 결합이고, 여기에 **8강 재사용**이 목표로 붙는다.

---

## 요구 ↔ 대응 장치

| 실전이 요구한 것 | 대입한 장치 | 차시 |
|---|---|---|
| 판정 규칙이 문서(`문제.md`)로 주어진다 | 규칙을 프롬프트에 옮겨 적지 말고 **파일을 읽힌다** | 2·4·8강 |
| 출력 양식이 빈 엑셀로 주어진다 | **"열 머리를 참조해서 채워넣어줘"** | 3강 |
| PDF·이미지에서 표를 만들어야 한다 | 취합 3원칙 + **"없으면 0이 아니라 빈칸"** | 2강 |
| 규칙으로 대상을 가려내야 한다 | 계산식을 문장이 아니라 **등식으로 못박기** | 3강 |
| 조건이 여러 축으로 섞여 있다 | **관점을 나눠 독립적으로** 검증 | 7강 |
| 결과가 맞는지 확인해야 한다 | **보존량 산식** + 안 걸었을 때 값과 대조 | 3강 |
| 확인할 수 없는 값이 있다 | 빈칸 · **「확인 필요」** | 2·5·7강 |
| 다음에 새 자료가 와도 써야 한다 | 스킬화 — **무엇을 고정하지 않을지** 정하기 | 8강 |

아래는 각 대응이 실제로 어떻게 붙는지다.

## 1. 문제 파일이 곧 「작업지침」이다 — 2·3·4·8강

시험 폴더는 이렇게 생겼다.

```
문제.md              ← 읽기 전용
문제한눈에보기.png    ← 흐름도
데이터/              ← 실습 대상
제출물/*.xlsx        ← 빈 양식. 새 파일 만들지 말 것
```

강의가 네 차시에 걸쳐 같은 발상을 반복했던 그 구조다.

| 강의 | 실전 |
|---|---|
| 2강 `작업방법참고.xlsx`를 읽히고 "규칙부터 요약해봐" | `문제.md` |
| 3강 "쿠폰별성과표에 **열 머리를 참조하여** 채워넣으세요" | 빈 양식 `제출물/*.xlsx` |
| 4강 AI가 만든 분류 기준 PDF를 다음 작업의 입력으로 | 판정 규칙 절 |
| 8강 `주문통합_작업지침.md` 범용화 | "다음 분기에 새 자료가 와도" |

**그래서 규칙을 프롬프트에 옮겨 적을 필요가 없다.** 파일을 읽히고, 출력 양식은 "열 머리를 참조해서"로 넘긴다. 프롬프트가 짧아지는 만큼 옮겨 적다 틀릴 여지도 사라진다.

### 첫 프롬프트는 규칙 복창

2강 실습1의 **"아직 종합하지는 마"**를 그대로 옮긴다.

> 먼저 `문제.md`를 읽고, 판정 규칙과 기준일, 제출 양식의 시트 이름과 열 머리를 나한테 요약해서 말해봐. **아직 자료를 읽거나 판정하지는 마.** 규칙 중에 애매하거나 서로 충돌하는 부분이 있으면 그것도 같이 말해줘.

2강에서 이 단계가 헤더 불일치와 날짜 3형식을 데이터가 망가지기 전에 잡았다. 실전에서도 같은 자리에서 규칙 해석의 미결 사항이 먼저 튀어나왔고, 판정에 들어가기 전에 합의할 수 있었다.

### 첨부 이미지도 지침의 일부다

`문제한눈에보기.png`는 흐름도처럼 보이지만 **텍스트에 없는 조건이 들어 있었다.** "파일명이 곧 계약번호", "양식이 제각각", 중간표를 만들라는 지시, 조항 번호가 계약마다 다르다는 것. 텍스트만 읽히면 이게 빠진다.

**지침으로 주어진 파일은 전부 읽힌다.** 요약본처럼 생겼다고 건너뛰지 않는다.

## 2. 비정형에서 표 만들기 — 2강

문제 1은 PDF 30건, 문제 2는 포스터 이미지 10개. **2강 계약서 8건이 그대로 확대된 형태**다.

두 문제 모두 흐름도 2단계에 **"중간 정리용 표, 제출 안 함"**이 명시돼 있었다. 추출과 판정을 분리하라는 게 문제의 지시였다는 뜻이다.

| 2강에서 배운 것 | 실전에서의 모습 |
|---|---|
| 빠뜨리지 않는다 | 파일 개수 = 중간표 행 수를 세서 확인 |
| 임의로 수정하지 않는다 | 날짜만 `YYYY-MM-DD`로 통일, 나머지는 원문 그대로 |
| 없는 것은 지어내지 않는다 | 조항이 없으면 **0이 아니라 빈칸** |

세 번째가 실전에서도 급소였다. 2강 CT-2026-005는 8건 중 1건만 금액 조항이 없어서 나머지 7건 패턴에 맞춰 0이 들어가기 딱 좋았다. 실전에서도 통지일 조항이 없는 계약에 0이 들어가면 **판정 결과가 통째로 뒤집힌다** — 통지마감이 종료일과 같아져 버리기 때문이다.

> 계약서에 안 적힌 항목은 지어내지 말고 비워둬. 특히 갱신통지일 조항이 없으면 0이 아니라 빈칸으로 해.

### 원문을 표에 붙여둔다

7강 "근거가 어느 파일 어디인지"의 실전형. 중간표에 **판독 근거 칸**을 하나 만든다.

- 계약서라면 → `근거조항` (제N조에서 읽었는지)
- 포스터라면 → `신청자격원문` (자격 문장 그대로)

특히 이미지 자료는 다시 열어 대조하는 비용이 크다. 원문을 표에 붙여두면 이후 모든 검증을 표 안에서 끝낼 수 있다.

## 3. 규칙 판정 — 1강 ⑥ + 3강

1강 구분으로는 **정답이 규칙으로 정해진 작업**이다. 분류(③)와 달리 감으로 판단할 여지가 없다.

3강 지침 6~9가 그대로 쓰인다 — **파생 값을 문장이 아니라 등식으로 준다.**

> 남은날 = 종료일 − 2026-06-28
> 만료임박 = 남은날이 0 이상 60 이하
> 자동연장주의 = 자동갱신 Y **그리고** 남은날 ≥ 0 **그리고** (남은날 − 갱신통지일) ≤ 30

그리고 4강의 **"라벨 목록은 사람이 못박는다"**가 여기서도 적용된다. 대상유형으로 쓸 값 세 개를 프롬프트에 열거해, AI가 "만료주의" 같은 범주를 새로 만들지 못하게 막는다.

### 판정 결과는 전수로 받는다

7강 **"충족했는지가 아니라 언급조차 안 했는지"**의 실전형이다.

> 대상만 보여주지 말고, **전 건에 대해** 판정 근거와 제외 사유를 표로 보여줘.

대상만 뽑아 보여달라고 하면 **잘못 빠진 건이 표에서 아예 사라진다.** 7강에서 "충족/미충족" 2지선다로 물으면 언급 없는 요구가 표에서 사라졌던 것과 같은 구조다.

## 4. 검산 — 3강, 그리고 3강만으로는 부족했던 것

3강의 원칙은 **축약 전후를 잇는 보존량을 하나 잡는 것**이다. 실전에서는 이렇게 붙는다.

```
전체 건수 = 대상 건수 + 비대상 건수
유형별 건수의 합 = 제출 파일 행 수
```

여기에 3강의 **"안 걸었을 때 값과 대조"**를 더한다. "조건 걸었어?"에 "네"는 증거가 아니다.

> 아무 조건도 안 걸었으면 나왔을 행 수와 실제 행 수를 나란히 보여줘.

### 산식이 다 맞는데도 틀릴 수 있다

실전에서 실제로 겪은 지점이다. 보존량 산식이 **세 개 다 맞아떨어졌고** AI는 "100% 정확합니다"라고 했다. 그런데 계산에 쓰인 남은날 값이 이랬다.

```
200, 300, 100, 250, 200, 180, 365, 90, 61
```

**9개 중 8개가 10의 배수고, 365는 대놓고 "1년"이다.** 실제 날짜에서 기준일을 뺀 값이 이렇게 떨어질 확률은 거의 없다.

5강과 3강이 한 자리에서 동시에 재현됐다.

> (5강) **"상당히 그럴듯하게 잘 지어낼 가능성이 높습니다"**
>
> (3강) 집계는 **행이 줄어드는 작업**이라 틀려도 눈에 안 띈다

**산식 검산은 내부 일관성만 본다.** 30건에서 25행이 나오는 흐름이 완벽히 맞아떨어져도, 그 흐름에 들어간 값 자체가 지어낸 것이면 산식은 아무것도 못 잡는다. 자기 출력을 자기가 검사하는 구조이기 때문이다.

**그래서 검산에는 원본으로 되돌아가는 독립 경로가 하나 있어야 한다.**

> 중간표의 **원값**을 전 건 그대로 출력하고, 거기서 파생값을 다시 계산해 아까 보고한 값과 나란히 대조해줘. 그리고 원본 파일 3건을 다시 열어 중간표와 맞는지 원문과 대조해줘.

2강이 검산에 "원본 세 파일의 줄 수를 각각 세라"는 **독립 경로**를 넣었던 이유가 이것이다. 결과물만 놓고 도는 검산은 아무리 정교해도 닫힌 고리다.

## 5. 확인할 수 없는 값 — 2·5·7강

세 차시가 같은 것을 다르게 부른다.

| 차시 | 표현 |
|---|---|
| 2강 | 조항이 없으면 **0이 아니라 빈칸** |
| 5강 | 추측이 들어가면 **추측이라고 표시** |
| 7강 | 없는 답은 빈칸도 거짓말도 아닌 **「확인 필요」** |
| 8강 | 애매하면 **물어보는 단계를 절차에 못박음** |

실전 문제도 같은 말을 한다. *"계약서에 적힌 내용만 근거로 판단하고, 확인할 수 없는 값은 추측하지 않습니다"*, *"포스터에 없는 조건은 그 정책에 없는 것으로 취급하고, 없는 조건을 추측해 적용하지 않습니다"*.

문제 2는 아예 **「확인 불가 정책 — 아무에게도 추천하지 않음」**이라는 별도 범주를 뒀다. 회원 명단으로 확인할 수 없는 조건이 붙은 정책은 통째로 제외하는 것이다. 7강의 「확인 필요」가 판정 규칙으로 승격된 형태다.

## 6. 관점을 나눈다 — 7강

문제 2는 판정 축이 10개(나이·거주지·취업·기업규모·월소득·중위소득%·연소득·무주택·학력·혼인)에 「확인 불가 정책」 판별까지 붙는다. **한 프롬프트에 다 넣으면 섞인다.**

7강이 "첫 번째 검증이야 / 이번엔 고객 입장에서 / 세 번째 검증이야"로 프롬프트를 나눴던 그대로다.

> 이번엔 **확인 불가 정책만 골라내는 검증**이야. 다른 축은 보지 마.
> 자격 원문을 정책마다 한 문장씩 끝까지 다시 읽고, 세 유형이 들어 있는지만 판정해줘.
> **비해당인 정책도 왜 아닌지 한 줄씩 써.**

문제가 *"표·소제목이 아니라 문장 안에 숨어 있을 수 있으니 끝까지 읽으세요"*라고 경고한 축이다. 조건 판독과 같은 프롬프트에 섞으면 놓치고, 하나 놓치면 그 정책에 매칭된 회원 수백 줄이 통째로 오답이 된다.

## 7. 다음에도 쓸 수 있게 — 8강

두 문제 모두 목표 칸에 8강이 그대로 들어 있었다.

> 다음에 새 자료가 와도 쓸 수 있게 **처리 방식을 남겨 두는 것까지**가 목표입니다.

한눈에보기 하단도 같은 말을 한다 — *"**AI에게 단계별로 지시해** 자동으로 처리하는 방식을 만드는 것이 목표입니다."*

8강 실습①의 **"이건 바꾸고 이건 유지해"** 구조를 그대로 쓴다.

| | 고정하지 않는다 | 그대로 유지한다 |
|---|---|---|
| 8강 | 파일명, 열 이름 | 표준 칸, 날짜 형식, 중복 처리, 검산 |
| 실전 | 폴더 경로, 파일명, 자료 건수, 기준일 | 판정 규칙과 계산식, 3원칙, 검산 항목 |

**범용화는 "무엇을 고정하지 않을지"를 정하는 일이다.** 규칙까지 같이 뭉개면 아무 데서나 도는 대신 아무것도 보장 못 하는 절차가 된다.

배포 단위는 폴더 하나다. 자료와 같은 자리에 스킬 폴더를 두면 그대로 넘길 수 있다 — 8강에서 스킬을 저장소 루트에서 `8강/.claude/skills/`로 옮겼던 판단이 그대로 적용된다.

## 강의에 없어서 실전에서 새로 필요했던 것

배운 장치로 덮이지 않은 자리도 있었다.

**① 규칙 해석의 경계는 AI가 못 잡는다.**

규칙 복창 단계에서 AI가 애매한 지점 두 개를 스스로 되물었지만, **정작 가장 위험한 하나는 못 잡았다** — 마감이 이미 지나 값이 음수가 되는 경우. "30일 이하"라는 규칙에 음수도 당연히 포함되는데, 조건을 코드로 옮길 때 하한이 슬쩍 생기면 그 건들이 통째로 사라진다. 실무적으로는 **기한을 이미 놓쳐 가장 급한 건**이라 놓치면 치명적이다.

4강의 "라벨 목록은 사람이 못박는다"를 한 단계 넓혀야 한다 — **경계값의 해석도 사람이 못박는다.**

**② 값의 생김새가 산식보다 먼저 이상을 알려준다.**

위 4절의 라운드 넘버 건. 검산 산식을 아무리 겹쳐도 못 잡던 것을, **결과값을 눈으로 훑는 것**이 잡았다. 3강이 "표본 5개를 손계산해 대조"를 검산 항목에 넣었던 이유가 이것이다.

**③ 문제가 명시한 예외 조항에 해당 건수가 0이면 의심한다.**

문제가 *"종료일이 직접 적혀 있지 않은 계약은 시작일과 계약 기간으로 계산합니다"*라는 조항을 굳이 넣어 뒀는데, 판독 결과 해당 계약이 0건으로 보고됐다. **쓸 이유가 없는 조항을 문제가 넣지 않는다.** 2강에서 8건 중 1건만 금액 조항이 빠져 있던 것과 같은 설계다.

이건 강의에 없던 관점인데, **지침 문서가 있는 작업 전반에 쓸 수 있다** — 지침이 다루는 예외에 해당 건수가 0이면 판독을 의심할 근거가 된다.

## 정리

- **문제 자체가 강의에서 배운 「작업지침 파일」이다.** 규칙을 옮겨 적지 말고 읽히고, 출력 양식은 "열 머리를 참조해서"로 넘긴다.
- **"아직 하지 마"로 한 번 끊는다.** 판정에 들어가기 전이 규칙 해석을 합의할 마지막 지점이다.
- **추출과 판정을 분리한다.** 실전 문제도 중간표를 만들라고 명시했다.
- **없는 값은 0이 아니라 빈칸.** 나머지 패턴에 맞춰 채우기 딱 좋은 자리가 항상 하나씩 있다.
- **판정 결과는 전수로 받는다.** 대상만 보면 잘못 빠진 건이 안 보인다.
- **검산에는 원본으로 되돌아가는 독립 경로가 필요하다.** 산식만으로는 닫힌 고리다.
- **관점을 섞지 않는다.** 축이 많을수록 한 번에 하나씩 잠근다.
- **범용화는 무엇을 고정하지 않을지 정하는 일이다.** 규칙은 유지하고 경로·건수만 뗀다.
