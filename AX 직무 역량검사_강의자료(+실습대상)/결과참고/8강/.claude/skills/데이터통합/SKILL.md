# 데이터통합

## 이 스킬을 쓰는 상황
사용자가 폴더 하나(또는 파일 여러 개)를 가리키며 "하나로 합쳐줘", "비교표로 만들어줘"라고 요청할 때 쓴다.
파일들은 같은 종류의 정보(주문/견적/실적 등)를 담고 있지만 출처마다 파일 형식과 열 이름이 다르다는 것을 전제로 한다.
특정 파일명이나 열 이름을 판단 로직에 미리 정해두지 않는다 — 매번 새로운 폴더, 새로운 파일 구성을 만난다고 가정한다.

## 절차

1. **폴더에서 표 파일 찾기**
   - 지정된 폴더(또는 사용자가 알려준 파일들) 안에서 표 형식 파일(.xlsx, .xls, .csv 등)을 모두 찾는다.
   - 작업지침 문서나 이전에 만든 결과 파일처럼 통합 대상이 아닌 파일은 제외한다. 대상 포함 여부가 애매하면 사용자에게 확인한다.
   - 각 파일의 원본 행 수(헤더 제외)를 세어 기록해 둔다 — 마지막 검산에 쓴다.

2. **각 열의 의미 파악**
   - 각 파일을 열어 헤더 이름과 상위 몇 행의 실제 값을 함께 확인한다.
   - 헤더 이름이 영어, 줄임말, 다른 표현이어도 값의 내용(문자 패턴, 날짜 형식, 숫자인지 텍스트인지, 콤마 포함 여부, 인코딩 등)을 보고 그 열이 무엇을 뜻하는지 추론한다.

3. **표준 칸 매핑 제안**
   - 파일들이 공통으로 담고 있는 정보를 바탕으로 표준 칸 목록을 정한다. 표준 칸은 도메인마다 다르다(예: 주문이면 주문번호·고객명·상품명·수량·금액_원·주문일·출처채널, 견적이면 거래처·품목·단가·수량·합계·견적일 등).
   - 각 원본 파일의 열이 표준 칸 중 어디에 대응하는지 매핑표(원본 파일 → 원본 열 → 표준 칸)를 만든다.
   - 어느 표준 칸에도 뚜렷이 맞지 않는 열, 여러 칸에 해당할 수 있어 보이는 열은 따로 표시해 둔다.

4. **나한테 확인**
   - 3번에서 만든 매핑표와 애매해서 표시해 둔 열을 사용자에게 보여주고 진행해도 되는지 확인받는다.
   - 애매한 열은 짐작해서 배정하지 않는다. 반드시 사용자에게 물어보고 답을 받은 뒤에만 다음 단계로 넘어간다.

5. **통합**
   - 확인된 매핑대로 모든 파일을 표준 칸 형식으로 변환한다: 날짜는 `YYYY-MM-DD`, 금액은 콤마 등 구분기호를 제거한 숫자만 남긴다.
   - 파일 간에 같은 항목을 가리키는 고유 키(예: 주문번호, 견적번호)가 겹치면 중복을 제거하고 한 줄만 남긴다. 어느 파일을 "먼저"로 볼지 기준이 불명확하면 사용자에게 확인한다.
   - 원본에 값이 없는 칸은 빈칸으로 둔다.

6. **행 수 검산**
   - 통합 후 행 수 = (각 파일의 원본 행 수 합) − (중복 제거 건수)가 맞는지 계산해서 사용자에게 보여준다.
   - 가능하면 금액처럼 합계를 낼 수 있는 값도 통합 전후로 비교해 차이가 없는지 확인한다.
   - 행 수나 합계가 예상과 다르면 결과를 내놓기 전에 원인(중복, 빠뜨린 파일, 잘못된 매핑)을 먼저 찾는다.

## 원칙

1. **빠뜨리지 않기** — 원본에 있는 행은 하나도 누락하지 않는다. 제외한 행이 있다면 이유(중복 제거 등)를 명시한다.
2. **바꾸지 않기** — 원본 값(이름, 품목, 금액 등)을 임의로 고치거나 반올림·수정하지 않는다. 형식만 표준 칸 규격(날짜, 숫자)에 맞춘다.
3. **지어내지 않기** — 원본에 없는 값이나 애매한 열의 배정을 추측해서 채우지 않는다. 빈칸은 빈칸으로 두고(0으로 채우지 않음), 모르면 사용자에게 묻는다.
