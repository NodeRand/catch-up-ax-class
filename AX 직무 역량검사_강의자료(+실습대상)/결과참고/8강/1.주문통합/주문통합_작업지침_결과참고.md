# 주문통합 작업지침 (범용)

## 목적

한 폴더에 흩어져 있는 주문 표 파일들을 하나의 표준 표로 통합한다.
**파일 이름과 열 이름은 매번 다를 수 있다.** 특정 파일명이나 특정 열 이름을 전제하지 않고,
파일을 열어 내용을 보고 판단한다.

## 표준 7칸 (고정)

통합 결과는 항상 아래 7칸으로 만든다. 이 칸 이름과 순서는 바꾸지 않는다.

| 칸 | 설명 |
|---|---|
| `주문번호` | 주문을 구분하는 키 |
| `고객명` | 주문한 사람 또는 회사 |
| `상품명` | 주문 품목 |
| `수량` | 주문 개수 |
| `금액_원` | 주문 금액(총액), 콤마 없는 숫자 |
| `주문일` | `YYYY-MM-DD` |
| `출처채널` | 어느 파일에서 왔는지. **여러 파일에 겹친 주문은 출처를 전부 기록** |

---

## 절차

### 1단계. 파일 찾기

폴더 안의 **표 파일을 전부** 찾는다. 파일명으로 고르지 않는다.

- 대상 확장자: `.xlsx`, `.xlsm`, `.xls`, `.csv`, `.tsv`
- 제외: `~$`로 시작하는 엑셀 임시파일, 숨김파일, 이전 실행으로 만든 결과 파일
- 찾은 파일 목록을 사용자에게 먼저 보여준다. **폴더에 있는데 통합 대상이 아닌 파일이 있으면 이때 확인받는다.**
- 처리 순서는 **파일명 오름차순으로 고정**한다. 이 순서가 중복 주문에서 **어느 행의 값을 남길지**와 **`출처채널`에 파일명을 나열하는 순서**를 정하므로, 실행할 때마다 결과가 달라지지 않도록 반드시 고정한다.

### 2단계. 파일 열어보기

각 파일의 **첫 행(헤더)과 상위 3~5행**을 읽는다.

- **엑셀**: 시트가 여러 개면 어느 시트가 데이터인지 확인한다. 애매하면 묻는다.
- **CSV**: 인코딩을 `utf-8-sig` → `cp949` → `utf-8` 순으로 시도한다. 한글이 깨지면 다음 인코딩으로 넘어간다.
- **헤더 위치**: 1행이 제목·설명이고 2~3행부터 헤더인 경우가 있다. 첫 행이 표 머리글로 보이지 않으면 아래 행을 확인한다.
- 파일별 **데이터 행 수**(헤더 제외)를 세어 기록해 둔다. 검산에 쓴다.

### 3단계. 각 열이 무엇인지 판별

열 이름만 믿지 말고 **이름 힌트 + 실제 값**을 함께 보고 판단한다.

| 표준 칸 | 이름 힌트 (예시일 뿐, 이것만 보지 않음) | 값으로 확인하는 방법 |
|---|---|---|
| `주문번호` | 주문번호, order_id, 협력사주문ID, 번호, No, ID | 값이 거의 전부 서로 다름(고유값 비율이 높음). 접두사+숫자처럼 일정한 패턴 |
| `고객명` | 고객명, name, 구매자, 거래처, 수요처 | 사람·회사 이름 문자열. `㈜`, `(주)`, `상사`, `산업` 등이 섞여 있음. 같은 값이 여러 번 반복됨 |
| `상품명` | 상품, 상품명, item, 품목, 품명, 자재명 | 문자열이고 값이 반복됨. 날짜·숫자로 해석되지 않음 |
| `수량` | 수량, qty, 개수, 주문수량 | 정수. 금액보다 자릿수가 훨씬 작음 |
| `금액_원` | 금액, amount, 결제액, 합계, 총액, 공급가액 | 정수 또는 콤마 포함 문자열. 자릿수가 큼 |
| `주문일` | 주문일, 주문일시, date, 일자 | 날짜로 해석 가능한 값 |
| `출처채널` | (원본에 없는 칸) | 파일에서 만들어 넣는다 (5단계 참조) |

**판별할 때 주의할 것**

- **단가는 금액이 아니다.** `단가`, `개당단가`, `unit_price`는 1개당 가격이다. 총액 열이 따로 있으면 그것을 `금액_원`에 넣는다. 총액 열이 없고 단가만 있으면 → **묻는다**(4단계).
- **날짜 열이 여러 개일 수 있다.** `납기일`, `납품예정일`, `delivery`, `등록일`은 주문일이 아닐 수 있다. 주문일로 볼 열이 명확하지 않으면 → **묻는다**.
- **이름과 값이 어긋나면 값을 믿는다.** 열 이름이 `금액`인데 값이 한 자리 정수면 수량일 수 있다. 이때는 넘겨짚지 말고 → **묻는다**.
- **표준 7칸에 없는 열**(`사양`, `규격`, `비고` 등)은 버릴지 남길지 → **묻는다**. 임의로 버리지 않는다.

### 4단계. 매핑표를 보여주고 확인받기

판별 결과를 아래 형식의 표로 만들어 사용자에게 보여주고, **진행 전에 확인을 받는다.**

| 파일 | 원본 열 | → 표준 칸 | 값 예시 |
|---|---|---|---|
| (파일명) | (열 이름) | (표준 칸 또는 "미사용") | 실제 값 2~3개 |

**반드시 물어봐야 하는 경우 — 추측해서 채우지 않는다**

1. 한 표준 칸에 들어갈 후보 열이 **둘 이상**일 때 (예: 날짜 열이 `주문일`과 `납기일` 둘 다 있음)
2. 표준 칸에 **대응하는 열이 없을** 때 (예: 주문번호나 고객명이 아예 없는 파일)
3. 열 이름과 실제 값이 **서로 맞지 않을** 때
4. **단가만 있고 총액이 없을** 때 → `수량 × 단가`로 계산해 넣을지, 비워 둘지
5. 날짜가 `01/15/2026` 같은 형태이고 **월/일 순서를 확정할 수 없을** 때 (아래 6단계 참조)
6. 표준 7칸에 **해당하지 않는 열**을 어떻게 할지
7. **주문번호 열이 없어** 중복 판정 기준을 정할 수 없을 때 → 무엇을 키로 볼지
8. 같은 주문번호인데 **파일마다 값이 다를** 때 → 어느 파일을 우선할지

질문할 때는 **파일명 · 열 이름 · 실제 값 예시 3개**를 함께 제시하고, 고를 수 있는 선택지를 준다.
사용자가 답하기 전에는 그 열을 임의로 매핑하지 않는다.

### 5단계. 값 변환

확인받은 매핑대로 각 파일을 표준 7칸으로 바꾼다.

**날짜 → `YYYY-MM-DD`**

- 시각이 붙어 있으면 **시각은 버린다** (`2026-01-07 15:00` → `2026-01-07`)
- 엑셀 날짜값은 그대로 날짜로 읽는다
- 다양한 표기를 모두 받아들인다: `2026-01-07`, `2026/01/10`, `2026.02.02`, `2026년 2월 2일`
- **`01/15/2026` 형태(월/일 순서 불명)** 처리 순서:
  1. 그 열의 **전체 값을 훑는다.** 첫 자리에 13 이상이 나오면 `DD/MM/YYYY`, 둘째 자리에 13 이상이 나오면 `MM/DD/YYYY`로 확정한다.
  2. 양쪽 모두 12 이하만 나와 확정할 수 없으면, 같은 주문번호가 **다른 파일에도 있는지 보고 그 파일의 날짜와 대조**한다.
  3. 그래도 확정할 수 없으면 → **묻는다.** 임의로 정하지 않는다.
- 날짜로 해석할 수 없는 값은 **빈칸으로 두고**, 어느 행이었는지 사용자에게 보고한다

**금액 → 콤마 없는 숫자**

- 콤마(`,`), 통화 기호, `원`, 공백을 제거하고 숫자만 남긴다 (`66,000` → `66000`)
- 숫자로 바꿀 수 없으면 **빈칸으로 두고** 보고한다
- **빈칸을 0으로 채우지 않는다.** 0으로 채우면 진짜 0원과 구분할 수 없다

**수량**

- 정수로 읽는다. 단위 글자가 붙어 있으면(`50개`) 숫자만 남긴다
- 음수나 이상값이 있으면 고치지 말고 그대로 두되 사용자에게 보고한다

**출처채널**

- 그 행이 **어느 파일에서 왔는지** 적는다
- 값은 **확장자를 뗀 파일명**을 쓴다 (`웹주문.xlsx` → `웹주문`)
- 이 단계에서는 파일별로 하나씩 적어 두고, **여러 파일에 겹친 주문은 6단계에서 합쳐 기록**한다

### 6단계. 통합

- 모든 파일의 행을 하나의 표로 모은다. **원본에 있는 행은 하나도 빠뜨리지 않는다.**
- **같은 `주문번호`가 두 파일 이상에 있으면 한 줄만 남긴다.**
- 남길 줄의 값(고객명·상품명·수량·금액·주문일)은 **1단계에서 정한 순서상 먼저 등장한 파일** 기준으로 한다.
- **`출처채널`에는 그 주문이 있었던 파일을 전부 기록한다.** 한 파일에만 있으면 그 파일명 하나, 여러 파일에 겹치면 **모두 나열**한다.
  - 구분자는 ` / `를 쓴다 (예: `웹주문 / 전화주문`)
  - 나열 순서는 **1단계의 파일 처리 순서**를 따른다 (예: `웹주문 / 전화주문 / 제휴주문`)
  - 같은 파일에 같은 주문번호가 두 번 나오더라도 파일명은 **한 번만** 적는다
- 중복으로 제거한 주문번호와 건수를 따로 기록해 둔다 (검산에 쓴다).
- 같은 주문번호인데 다른 칸의 값이 서로 다르면, 임의로 고르지 말고 **어느 파일을 따랐는지와 함께 사용자에게 보고**한다.
- 원본 값(고객명, 상품명, 금액)은 **고치거나 반올림하지 않는다.** 형식만 표준에 맞춘다.

### 7단계. 검산

아래 표를 만들어 사용자에게 보여준다.

| 항목 | 값 |
|---|---|
| 파일별 데이터 행 수 | 파일마다 각각 |
| 원본 행 수 합계 | (파일별 합) |
| 중복으로 제거한 건수 | |
| **통합 후 행 수 (기대)** | 합계 − 중복 제거 건수 |
| **통합 후 행 수 (실제)** | |
| 일치 여부 | 기대 = 실제 |

추가로 확인한다.

- **금액 합계**: 통합 전 합계 − 중복 제거된 행의 금액 = 통합 후 합계
- **키 양방향 대조**: 원본 주문번호 집합과 통합 결과 집합을 비교해 **누락 0건, 초과 0건**임을 확인
- **출처 기록 대조**: `출처채널`에 적힌 파일명을 모두 세었을 때, 파일별 등장 횟수가 그 파일의 원본 행 수와 같아야 한다. 합계는 원본 행 수 합계와 같아야 한다.
- **빈칸 개수**: 칸별로 빈칸이 몇 개인지 보고 (0으로 채워지지 않았는지 확인)

**기대와 실제가 다르면 결과를 내지 말고 원인부터 찾는다.** 빠진 주문번호를 목록으로 제시한다.

### 8단계. 산출물

- 통합 결과 파일 (기본값 `주문통합_결과.xlsx`, 사용자가 이름을 정하면 그대로 따른다)
- 검산표
- 처리 중 보고할 사항: 매핑 결과, 빈칸으로 남긴 값, 중복 제거 내역, 값 충돌 내역

---

## 원칙

- **빠뜨리지 않기** — 원본 행은 하나도 누락하지 않는다. 제외한 행이 있으면 이유(중복 등)를 밝힌다.
- **바꾸지 않기** — 원본 값을 임의로 고치거나 반올림하지 않는다. 형식만 맞춘다.
- **지어내지 않기** — 원본에 없는 값을 추측해 채우지 않는다. 애매하면 **묻는다.**
- **빈칸 ≠ 0** — 값이 없으면 비워 둔다.
- **확인 먼저** — 열 매핑은 사용자 확인을 받은 뒤에 실행한다.
